The repository, releases and [community guide](https://github.com/BGGBTAC/hapi-evolved/blob/main/COMMUNITY.md) are the central
entry points. Publish only links and claims that are available in the selected
revision. Do not present a source preview as production-ready, promise all models,
or describe the fixture recording as a live agent run.

not an approved DEV submission. The [current AI-content guidelines](https://dev.to/guidelines-for-ai-assisted-articles-on-dev/),

including one's own. The [new disclosure tiers](https://dev.to/devteam/introducing-ai-disclosure-on-dev-tools-for-nuance-clarity-and-better-feeds-34mk/)
do not waive those community standards. Do not automatically publish this launch
copy or AI-generated replies on DEV. The same factual project introduction can
be used on this project's own GitHub Discussions.

A future DEV contribution needs an appropriate original technical account and
compliance with the then-current policy, as well as a connected maintainer account.
Do not disguise a promotional post as a tutorial or invent a maintainer's personal
experience. Predominantly agent-written content must use the fully autonomous
disclosure if published on a venue that allows it. Check for duplicates before any
authorized publication and record the resulting public URL, not merely an API request.

## Hacker News: human submission only

As checked on 2026-10-16, [HN's guidelines](https://news.ycombinator.com/newsguidelines.html)
prohibit generated text, AI-edited comments and automated posting. This file is a
fact sheet, not a ready-to-post HN submission. The maintainer must write the title
and personal introduction themselves and submit it manually. Do not reuse an AI
draft or automate replies. Recheck the rules when posting.

Facts the maintainer can verify while writing:

- Independent fork of `tiann/hapi`, AGPL-3.0-only with attribution preserved.
- Linux + Docker Compose, Bun 1.3.14, about 12 GiB RAM for stack and one runner.
- Source distribution; no official registry images or upstream migration support.
- Managed browser provider login needs the separately installed local host service.
- Repository access, execution profiles, native subscriptions and cloud-memory
  spending are separate controls.
- Demo media use synthetic data and provider/GitHub fixtures; no model call is shown.
- Material AI assistance in development; actual tests and review limits belong in
  the selected release notes.
- Pilot feedback and focused contributions are welcome through GitHub.

The maintainer's personal reason for building the fork should be their own account.
[Show HN](https://news.ycombinator.com/showhn.html) expects something people can try,
and a maker who is available to discuss it. Link the usable project, choose a time
when the maintainer can respond, and do not solicit votes or coordinated comments.

## r/selfhosted

The [rules checked on 2026-10-16](https://www.reddit.com/r/selfhosted/about/rules.json)
require promoted apps to be production-ready and documented. Projects younger than
three months belong only in the current New Project Megathread. This source preview

Before any later contribution, check the actual current megathread and rules;
neither age nor a published tag makes the readiness requirement disappear.
Never seed comments in unrelated support threads or send unsolicited bulk messages.

## Follow through

The first-month targets and counting rules are in [COMMUNITY.md](https://github.com/BGGBTAC/hapi-evolved/blob/main/COMMUNITY.md).
During normal maintenance, review incoming Q&A, issues and voluntary pilot reports;
convert reproducible problems into focused issues and link the eventual fix back.
Keep first contributions small and explain review requests. Release notes should
credit accepted contributions and distinguish reported outcomes from target values.

No automated outreach schedule, artificial engagement, hidden usage collection,
paid campaign or guaranteed support turnaround is established by this launch.
Keep a simple dated update in Announcements when there are actual results to share.
